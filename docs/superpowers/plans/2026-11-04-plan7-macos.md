# macOS Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `brp` builds, runs, and ships natively on macOS (issue #17).

**Architecture:** One `macos` module per platform-bound crate (capture, audio), mirroring the
`linux`/`windows` modules behind the existing traits; VideoToolbox through the existing FFmpeg
paths; links through LaunchServices and Apple Events; a bundle and a flat archive from CI.

**Tech Stack:** Rust 2024, objc2 0.6 family (ScreenCaptureKit, CoreMedia, CoreVideo, Foundation,
CoreGraphics), CoreAudio C API, FFmpeg 8.1 VideoToolbox, GitHub Actions `macos-latest`.

**Spec:** `docs/superpowers/specs/2026-11-04-macos-port-design.md`

## Global Constraints

- Minimum macOS 14.0 (`MACOSX_DEPLOYMENT_TARGET=14.0`, `LSMinimumSystemVersion` 14.0).
- Bundle identifier `io.github.gtkacz.openstream`; executable `brp`; scheme `brp`.
- Release asset names: `brp-<version>-macos-aarch64.tar.gz` (updater), `OpenStream-<version>-macos-aarch64.zip` (bundle).
- `cargo fmt`, `cargo clippy --workspace --all-targets -D warnings`, `cargo test --workspace` stay green on Linux; the macOS job runs the same three.
- No new C/Swift build steps in the crates.

## Review Focus

1. Screen Recording permission refused → a clear error in the share dialog, not a hang.
2. A source that disappears (window closed, display unplugged) between listing and start → `SourceLost`.
3. `Only` audio with none of the chosen apps running → silence, then audio once one starts.
4. A `brp://` click while a room is open → a second window joins; the open room is untouched.
5. An update from inside `OpenStream.app` → swaps `Contents/MacOS` and relaunches the new binary.
