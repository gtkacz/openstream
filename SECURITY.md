# Security Policy

## Supported versions

Security fixes are applied to the latest code on the default branch. Tagged
releases are supported when practical; users should upgrade to the newest
release after a security fix is published.

## Reporting a vulnerability

Please **do not** open a public issue for a suspected security vulnerability.
Instead, submit a private report through [GitHub's private vulnerability
reporting flow](https://github.com/gtkacz/brp_sharing/security/advisories/new).

Include, where possible:

- a clear description of the issue and its impact;
- affected versions, operating systems, and configuration;
- reliable reproduction steps or a minimal proof of concept;
- any proposed mitigation or fix.

Tickets, persistent identity keys, settings files, logs, and crash dumps can
contain sensitive session information. Redact them before sharing a report.
Do not include real room tickets, private keys, credentials, or screenshots of
private sessions.

We will acknowledge a report, investigate it, and work with the reporter on a
fix and coordinated disclosure. Please allow time for a fix before disclosing
details publicly.
